# 城院小狮 · 校园智能助手

东莞城市学院第二届「智创全域，数启校园」智能体设计大赛参赛作品的网页版。手机扫码就能用，也可以「添加到主屏幕」当 App 用。

> 名字、头像、首页推荐问题都在 `src/lib/config.ts` 里，一处修改全站生效。

## 已经实现的功能

| 功能 | 说明 |
|---|---|
| 有据可查的问答 | 每次提问先检索 `knowledge/` 里的校园资料（含从学校官网整理的 7000 多篇页面），回答里用 ①② 标出处，点开能看到原文、资料更新日期和官网原文链接 |
| 不知道就说不知道 | 资料里没有答案时明确说没有，不编造；这类问题自动进入后台「待补充」 |
| 听得懂追问 | "那具体怎么操作？"这类追问会结合上一句一起检索；换了话题则不会被上一句带偏 |
| 实时联网搜索 | 校园资料不足、需要最新消息或用户要求联网时，调用 DeepSeek Search；必要时用 Fetch 读取网页正文，回答带可点击出处 |
| 拍通知 → 加日历 | 发通知截图或文字，自动提取时间、地点、要带的东西，生成日程卡片，一键导入手机日历（带提醒） |
| 生成式界面 | 回答不只是文字：日程卡片、出处角标、识图过程、检索步骤都是可交互的组件 |
| 点赞 / 点踩 | 点踩的回答进入后台「待补充」，形成"发现问题 → 补资料 → 标记已补充"的闭环 |
| 管理后台 `/admin` | 提问量趋势、有资料可答比例、满意度、回答首字时间、待补充问题、知识库管理与一键重新导入 |
| 演示模式 | 没配置大模型 Key 时自动进入，用模拟回复跑通全部界面，方便调样式 |
| 手机体验 | 适配手机屏幕和刘海屏、深色模式、输入法回车不误发、图片上传前自动压缩、对话刷新不丢 |
| 微信打开引导 | 微信内访问时显示右上角「··· → 在浏览器中打开」引导；支持复制完整链接，复制受限时可长按手动复制，也可继续在微信中使用 |

## 技术栈

- **Next.js 16 + React 19 + TypeScript**：前后端写在一个项目里，部署简单
- **Tailwind CSS 4 + shadcn/ui（Base UI）**：界面组件，主题色在 `src/app/globals.css`
- **Vercel AI SDK 7**：流式对话、工具调用、生成式界面
- **任意 OpenAI 兼容的大模型接口**：目前用 DeepSeek（对话 + 识图）和硅基流动（嵌入 + 重排），换成阿里云百炼、火山方舟等只需改配置
- **Node 自带的 SQLite**：存提问记录、反馈和知识库索引（FTS5 全文索引 + 向量），一个文件就是整个数据库

## 本地运行

需要 Node.js 24 和 pnpm。

```bash
pnpm install
```

```bash
cp .env.example .env.local
```

```bash
pnpm dev
```

打开 http://localhost:3000 。`.env.local` 里不填 `LLM_API_KEY` 就是演示模式。

互动回复已接入聊天工具：美食菜单、办事清单、考试备忘、英语复习、联系卡、地点卡和日历。美食使用已整理的有限餐食与历史价格；办事和联系方式须有本轮资料或用户原文依据；考试卡须提供明确日期。课表因没有真实数据已移除。

本地组件预览在 `/preview/map`，仅开发模式开放，可切换上述 7 种交互。预览本身不调用模型、不提交办理、不保存聊天；其中考试为标明的示例数据。地点卡已接入高德 JS API 2.0 与真实 POI 查询，需配置 `AMAP_JS_API_KEY`、`AMAP_SECURITY_JSCODE`；有多个候选地点时先由用户确认，再打开高德导航。正式聊天使用工具返回的数据，日历导出后需要用户自行导入。

常用命令：`pnpm lint`（代码检查）、`pnpm typecheck`（类型检查）、`pnpm build`（生产构建）、`pnpm kb:ingest`（导入知识库）、`pnpm kb:ocr`（转写官网正文里的图片和附件）、`pnpm kb:eval`（检索质量评测）。

## 接入大模型

一共四种模型，都走 OpenAI 兼容接口，在 `.env.local`（本地）或 `.env`（服务器）里配置，完整说明见 `.env.example`。我们目前的组合：

| 用途 | 服务商 | 模型 | 不配置时 |
|---|---|---|---|
| 对话 | DeepSeek | `deepseek-flash`（关闭思考模式） | 演示模式 |
| 识图（拍通知、海报） | DeepSeek | `deepseek-flash` | 不支持发图片 |
| 嵌入（语义检索） | 硅基流动 | `Qwen/Qwen3-Embedding-8B`（4096 维） | 只用关键词检索 |
| 重排（给候选资料精排） | 硅基流动 | `Qwen/Qwen3-Reranker-8B` | 只用粗排结果 |

- **一定要关掉 DeepSeek 的思考模式**（`.env.example` 里已写好 `LLM_EXTRA_BODY`）：开着的话每次回答前要先"思考"2～7 秒，关掉后约 0.5 秒出第一个字，校园问答用不上长推理。
- 服务器在香港：OpenAI、Claude、Gemini 的官方接口在香港不可用，请用国内服务商。
- 模型名要填接口里的 ID，不是网页上的显示名；可以用 `GET {BASE_URL}/models` 查。

## 检索是怎么做的

### 实时联网

已按 [DeepSeek Search / Fetch 官方文档](https://api-docs.deepseek.com/zh-cn/guides/search/) 接入 `POST /v1/tools/search` 与 `POST /v1/tools/fetch`。本地知识库照常检索；资料不足、涉及最新消息或用户要求联网时，模型调用联网工具。学校相关问题优先搜索 `site:dgcu.edu.cn`，摘要不足时再读正文。前端显示搜索/读取进度，并把联网来源和知识库来源统一编号，可点开摘要和原文。

对话模型使用 DeepSeek 官方接口时自动复用现有 `LLM_API_KEY`；其他服务商需单独设置 `DEEPSEEK_SEARCH_API_KEY`。`WEB_SEARCH_ENABLED=false` 可关闭；演示模式关闭联网。`/api/status` 的 `webSearch` 表示配置已启用，不代表每一次查询都成功。单次请求限时 20 秒，暂时错误最多重试一次，单轮最多 4 次联网调用；失败或无结果会明确提示，继续使用已有校园资料。

联网来源与知识库共用数字出处角标，回答正文不展示原始网址。点击角标打开摘要卡片，再通过「查看原始出处」访问网页；前端会把模型偶尔返回的网址转成已登记来源的编号，复制回答也使用相同格式。

Search 和 Fetch 按官方规则独立按次计费，不会因为对话使用 DeepSeek 自动免费。协议回归验证：`pnpm test:web-search`；真实 Search / Fetch 验证：`pnpm smoke:web-search`（读取本地模型配置，会实际调用接口）。

### 校园知识库

每次提问分三步找资料，再交给大模型组织回答：

1. **召回**：SQLite 全文索引按关键词（含"饭堂 = 食堂"这类同义词）找 80 段，同时用语义向量找最相似的 40 段（换种问法也能找到）
2. **粗排**：综合关键词覆盖度、标题是否命中、资料类型（办事资料 > 通知 > 新闻）、栏目、时效打分
3. **精排**：重排模型逐段判断"这段资料和问题有多相关"，再结合资料权重排出最终 5 段

几个提速的设计：关键词候选不等语义向量、先送去重排，向量回来后只把新找到的候选补一次重排；重排拆成每批 10 段并行；嵌入和重排接口偶尔排队时自动补发请求，谁先回来用谁。

**资料里有没有答案**：重排最高分低于 `RERANK_MIN_SCORE`（默认 0.3）判为资料不足；分数够但大模型读完资料发现答不了时，会固定回答"这个我暂时没有可靠的资料"，这两种情况都会进入后台「待补充」。

### 评测结果

`pnpm kb:eval compare` 用 43 个标好答案的问题对比四种配置（2026-10-13，本机测试）：

| 配置 | 调参题·第一条就对 | 新题·第一条就对 | 新题·前三条有对的 | 新题·有无资料判断对 | 检索耗时（中位） |
|---|---|---|---|---|---|
| 只用关键词（接入前） | 67% | 54% | 54% | 61% | 0.02 秒 |
| 关键词 + 语义向量 | 81% | 54% | 77% | 72% | 0.3～0.7 秒 |
| 关键词 + 重排 | 95% | 54% | 77% | 83% | 0.7～0.9 秒 |
| 关键词 + 语义向量 + 重排（现在） | 95% | 77% | 92% | 83% | 1.3～1.5 秒 |

「调参题」是调检索规则时用过的 25 个问题，「新题」是没参与调参的 18 个口语化问题（如"电脑坏了学校有地方修吗""学校在东莞哪个镇"），更能说明真实效果。题目和标准答案在 `scripts/kb-eval.ts`，补充资料后可以重新跑一遍。

另有 10 个「附件题」，答案只在官网正文图片或附件里（如"2025-2026学年什么时候放寒假""休学要走哪些审批环节"），命中的必须是有正文的资料。用 `pnpm kb:ocr` 转写前（只有占位页）第一条就对 0/10、前三条有对的 1/10，转写后 7/10、10/10（关键词 + 语义向量 + 重排）；上面 43 题的成绩不变。

## 知识库

资料放在 `knowledge/` 文件夹，一个主题一个 Markdown 文件，详细写法见 [knowledge/README.md](knowledge/README.md)。

- `knowledge/官网/`：从学校官网抓取、自动清洗的 7381 篇页面（学校概况、通知公告、教务处、学生处、图书馆等 17 个栏目），由 `pnpm kb:import-site` 生成，不要手改
- `knowledge/官网附件/`：官网上正文是图片或附件的页面（校历、收费标准、休学/复学等办事流程、学工发文），由 `pnpm kb:ocr` 用识图模型转写成文字，这样"什么时候放寒假""休学要走哪些环节"也能直接回答。重新生成 `官网/` 不影响这里；没能转写的页面列在 `_跳过清单.md`。Word 附件需要本机装有 LibreOffice
- `knowledge/` 根目录：团队自己整理的资料，检索时优先于官网页面。现有三份根据官网整理，**比赛前请逐条核实**，再补充你们选定方向的资料
- `knowledge/餐饮社媒/`：逐店保留出处和日期的历史评价、图片关联及营业待核说明。原始表格中未核查的地址、价格、电话和营业时间不直接进入答案；候选图片和同名冲突保存在项目根目录 `outputs/food-knowledge-2026-10-26/` 的结构化清单中。图片由 `public/knowledge-food/` 提供，现有导入器即可读取；`pnpm kb:food:validate` 用隔离数据库验证导入与检索。

改完资料后：重启服务、在后台点「重新导入知识库」、或运行 `pnpm kb:ingest`，三选一。只有改动过的段落会重新计算向量。

## 管理后台

在 `.env` 里设置 `ADMIN_PASSWORD`（足够长的随机密码）后，访问 `/admin` 登录。没设置时后台关闭。

## 部署到香港服务器

香港服务器**不需要备案**，有域名就能用 HTTPS（拍照、语音、推送等浏览器功能都要求 HTTPS）。服务器内存建议 2GB 以上（1 万段资料的向量常驻内存约 170MB）。

1. 服务器安装 Docker（含 docker compose 插件）
2. 买一个域名，添加 A 记录指向服务器 IP；服务器防火墙放行 80、443 端口
3. 把 `web` 文件夹上传到服务器（或 `git clone`），进入该目录
4. 复制 `.env.example` 为 `.env`，填好大模型 Key、`ADMIN_PASSWORD`，并加一行 `DOMAIN=你的域名`
5. 启动：

```bash
docker compose up -d --build
```

几十秒后访问 `https://你的域名` 即可，证书由 Caddy 自动申请和续期。第一次启动会在后台给全部资料计算向量（约 6 分钟），算完之前语义检索只覆盖已算好的部分，日志里出现「知识库已同步」就是算完了。

- 看日志：`docker compose logs -f app`
- 更新代码后重新部署：再执行一次上面的启动命令
- 只改了知识库：直接改服务器上的 `knowledge/`，然后在后台点「重新导入」，不用重新构建
- 数据都在 Docker 卷 `app_data` 里，备份：`docker compose cp app:/app/data ./backup`

## 常见问题

**回答一直不动，最后一下子全出来？** 中间有代理在压缩或缓冲响应。本项目已关闭压缩；如果你在 Caddy 前面又加了 Nginx 或 CDN，需要关掉它们对 `/api/chat` 的缓冲和压缩。

**图片发不出去？** 没有配置 `VISION_MODEL` 时识图功能关闭。

**每次回答前要等好几秒？** 先看日志里的耗时：「首字」比「检索」多出好几秒，多半是对话模型开着思考模式，检查 `LLM_EXTRA_BODY`；「检索」本身慢，多半是嵌入或重排接口在排队。实测硅基流动的 `Qwen3-Embedding-8B` 有时排队 5～15 秒（检索不会傻等，超时就只用关键词候选，但语义检索的效果就没了），同平台的 `Qwen/Qwen3-Embedding-4B` 稳定在 0.1 秒左右。换模型只需改 `EMBEDDING_MODEL` 再运行 `pnpm kb:ingest`，会重新计算全部向量（约 6 分钟）。

**本机测试时偶尔报"self-signed certificate in certificate chain"？** 电脑上的代理软件（如 Clash 的 TUN 模式）拦截了 HTTPS 连接，把大模型接口的域名设为直连即可；服务器上不会有这个问题。

**提示排队？** 默认全站滚动一分钟最多启动 20 次（`CHAT_RATE_LIMIT`），同时处理 5 个（`CHAT_CONCURRENCY`），等待队列上限 40（`CHAT_QUEUE_CAPACITY`）。自动轮到后开始回答，停止可取消；等待 3 分钟超时。队列保存在单个服务进程内，重启会中断等待；多进程部署需共享队列。
