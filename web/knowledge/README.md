# 知识库资料怎么写

这个文件夹里的每个 `.md` 文件都会被导入知识库，智能体回答问题时只依据这里的内容，并标注出处。

## 规则

- 一个主题一个文件，比如 `食堂.md`、`图书馆.md`、`奖助学金.md`。可以建子文件夹分类。
- 文件名或文件夹以 `_` 开头的不会入库（模板、草稿放这里），`README.md` 也不会入库。
- 每个 `##` 小标题下的内容会切成一段，检索时按段落匹配。**一段只讲一件事**，标题写清楚，效果最好。
- 小标题直接写成同学会问的问题效果更好，例如「## 图书馆几点开门？」。

## 文件头（必填）

每个文件最上面写这几行：

```
---
title: 图书馆
category: 校园设施
source: https://资料出处的网址（没有网址就写"学生手册 2026 版第 12 页"这类说明）
updated: 2026-10
---
```

- `title`：资料标题，会显示在回答的出处里
- `source`：出处，评委问"这个答案哪来的"时就靠它
- `updated`：资料更新时间，过期的资料要及时改

## 改完怎么生效

三种方式任选一种：

1. 重启服务（启动时会自动同步）
2. 管理后台 `/admin` →「知识库」→「重新导入」
3. 在 `web` 目录运行 `pnpm kb:ingest`

只有新增或改动过的段落会重新计算向量，不会浪费额度。

## 现有资料

- `学校概况.md`、`校园设施.md`、`交通出行.md`：根据学校官网等公开信息整理，**用于比赛前请逐条核实**，并补充食堂、教务、社团等你们选定方向的资料。模板见 `_模板.md`。
- `官网/`：从学校官网抓取的页面，由脚本自动清洗生成，**不要手改**（重新生成时会整个覆盖）。
- `官网附件/`：官网上正文是图片或附件的页面（校历、收费标准、办事流程、发文通知等），由 `pnpm kb:ocr` 用识图模型转写成文字，文件名和 `官网/` 里的一一对应。转写可能有个别错字，发现了可以直接改：重新运行时已转写过的会跳过，不会覆盖（加 `--force` 才会重新转写）。没能转写的页面和原因列在 `_跳过清单.md`。

团队自己整理的资料检索时比官网页面优先；同一件事两边说法不一致时，以自己核实过的为准，并在文件头 `source` 里写清出处。

## 重新导入官网页面

拿到新抓取的官网资料（每个页面一个 `.md`，按栏目分文件夹）后，在 `web` 目录运行：

```bash
pnpm kb:import-site 抓取资料所在的文件夹
```

脚本会去掉导航、页眉页脚、"上一篇/相关新闻"等内容，把被拆碎的句子拼回来，跳过列表页和重复页面，按栏目和标题标注资料类型（办事资料 / 通知 / 新闻，检索时新闻降权）。正文是图片或附件的页面（如校历、办事流程图）只保留标题和原文链接，回答时会引导同学点开原文。

接着把这些页面的图片和附件转写成文字（只处理还没转写过的，写到 `官网附件/`）：

```bash
pnpm kb:ocr
```

脚本逐篇打开原文网址，找出正文里的图片和 PDF / Word 附件，用识图模型（`VISION_MODEL`）转写；请求学校网站时逐个发出、间隔 1.5 秒。Word / Excel 附件要先用 LibreOffice 转成 PDF，电脑上没装 LibreOffice 时会跳过这类附件。常用选项：`--dry-run`（只列出找到的图片和附件，不调用模型）、`--only 校历`（只处理标题含"校历"的）、`--force`（已转写的也重新转写）。转写过的页面入库时，`官网/` 里对应的占位页不再入库。

最后运行 `pnpm kb:ingest` 导入。
